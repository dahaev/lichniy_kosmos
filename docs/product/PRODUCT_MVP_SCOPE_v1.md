# Личный космос 2.0 — MVP scope v1

Дата: 2026-11-11. Статус: проект спецификации для согласования.

## Решение

Полностью новая реализация на Go + Vue 3/TypeScript + PostgreSQL. Предыдущая версия 0.13.4 служит источником функциональных требований и инвариантов, не исходным кодом для переноса. Визуальный эталон главной страницы — скриншот, предоставленный владельцем 11.11.2026. Исходников и описания всех анимаций в текущем пакете нет.

## Основной сценарий

Публичный сайт → активация кода без аккаунта ИЛИ email OTP и привязка кода → отдельная анкета услуги → подтверждение → локальный астрономический расчёт → сохранение заказа и списание одного доступа → фоновая генерация текста и PNG → просмотр карты, текста, иллюстрации → скачивание PDF/TXT/PNG → повторное открытие без новой генерации.

## Критичные инварианты

1. Один доступ → максимум один заказ с зафиксированной анкетой. Идемпотентность и контроль конкуренции на уровне БД.
2. Проверка/привязка ещё не означает расход права на заказ.
3. Свой заказ доступен только его владельцу/допустимой кодовой сессии; перенос кодового результата в кабинет явный.
4. Астрономические данные рассчитывает сервер; при неизвестном времени не выдумывать дома и углы.
5. Контракт текста исходной спецификации: 8 тематических разделов, 1800–2700 слов.
6. Сохранённый текст или изображение не генерируются заново при повторном открытии либо локальном создании PDF.
7. Неизвестный исход платного ИИ-запроса требует ручной проверки, а не слепого повтора.
8. При ошибке астрономического расчёта право не расходуется.
9. PDF формируется из сохранённых материалов; нужны завершённые текст и изображение.
10. Минимальные операционные процессы: тестирование восстановления после рестарта, резервные копии и секреты вне Git.

## Не входит в MVP

Сайт не принимает оплату; корзина/checkout и банковские webhooks не нужны в первом релизе. Не реализуются Seller API Ozon, автоматическая доставка кодов, совместимость пары, личный год, журнал, история обращений и полноценная панель управления продажами/статистикой.

## Пользовательские сценарии приёмки

- U-A: кодовый вход → анкета → расчёт → готовый результат → повторный вход по тому же коду.
- U-B: email OTP → привязка одного/нескольких кодов → независимые анкеты/заказы → кабинет.
- U-C: ранее созданный кодовый результат → привязка к email → тот же заказ и файлы.
- U-D: ошибочный/заблокированный/чужой/использованный код; повторные запросы; конкуренция.
- U-E: неизвестное время, исторический часовой пояс, неполные данные и ошибки расчёта.
- U-F: прерывание вкладки и рестарт сервера во время генерации, сохранение готовых этапов и запрет неопределённых платных повторов.
- U-G: скачивание PDF/TXT/PNG только с соответствующим доступом, без новых ИИ-вызовов.
- U-H: минимальная защищённая операция владельца: выпуск партии, CSV, блокировка, проверка статуса.
