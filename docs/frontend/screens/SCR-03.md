# SCR-03 — Проверка данных

Срез: V2. Маршрут: `/create/review`. Композиция сцены: `review` (равна `intake.time`, тест `compositions.spec.ts`; сцена в SCR-03 не меняется).

Статус: **реализация на моке принята владельцем 12.11.2026 (Р12, Р13).** Стадия 0 утверждена 12.11.2026: контракт и мок (Р1–Р7), визуальная спецификация с корректировками (Р8–Р11). Backend `profile-checks` — срез B1. Ход реализации и приёмки — «Журнал реализации» в конце.

## 0. Спецификация

**Источники**

- SCREEN_SPEC_MVP_v2: §1 (сквозной путь), §2 (реестр), §4 (тексты подсказок времени), §5 (SCR-03), §12 (E2E-03).
- MOTION_SPEC: M03, M04, §5 (reduced motion), MOT-02, MOT-03.
- DESIGN_SYSTEM: §2, §4 (токены), §5 (типографика), §6 (`Field`, `PrimaryCTA`, `ProgressStep`), §7 (`/create/review`: editorial-сводка, вертикальный ритм без таблицы с рамками; акцент «Проверить и изменить»).
- ARCHITECTURE_MVP_v2: §8.3 п. 2, §12.2 (DST), §15.1–15.4, §16.6, §22 (Q10).
- SCR-02: черновик `cosmos.intake.v1`, шаги `/create?step=…`, `reachableStep` (§0.6), каркасы (§0.4), тексты полей (§0.5), токены motion (§2.1), M03 (§2.3), reduced motion (§2.4), C26.
- `ui-ux-pro-max` (`--domain ux`): Focusable Error Summary, Error Placement, Error Messages, Content Jumping, Submit Feedback, Reduced Motion, Excessive Motion.

**Место в сценарии:** SCR-02 (четыре шага) → **SCR-03** → SCR-04 `/create/access` → SCR-05 `/create/consent` → SCR-06 `/orders/:id/creating`.

**Что не входит:** доступ, коды, email, согласие, создание заказа, расход доступа, backend `profile-checks` (срез B1), выбор одного из двух моментов при переводе часов (Q10, срез B1), изменение SCR-01, SCR-02 и сцены.

### 0.1. Требования

1. Полный профиль: имя, дата рождения, выбранное место, время или «неизвестно», источник и точность (SCREEN_SPEC §5).
2. У каждого блока «Изменить» — возврат на нужный шаг `/create?step=…` без потери остальных полей (§5, M04).
3. Клиентская проверка черновика; серверная — `POST /api/v1/profile-checks` при каждом входе на review, ошибки показываются до шага доступа (§5, ARCH §8.3, Р5).
4. «Продолжить» → `/create/access` только после ответа 200. Заказ не создаётся, доступ не расходуется (§5, M04).
5. Четыре параметра появляются последовательными мягкими акцентами, но читаются сразу; при reduced motion — без stagger (M04, MOTION §5).
6. Для неизвестного времени не обещать дома и асцендент (SCREEN_SPEC §4).
7. Данные рождения не попадают в URL и аналитику (SCREEN_SPEC §4).

### 0.2. Контракт `POST /api/v1/profile-checks`

Источник истины — `api/openapi.yaml` (`checkProfile`, версия `0.2.0-v2`). Публичный, с лимитом частоты, ничего не сохраняет.

**Запрос** `Profile` (ARCH §15.4), неизвестные поля запрещены:

| Поле | Правило | Из черновика SCR-02 |
|---|---|---|
| `name` | 1–60 символов Unicode после trim | `draft.name` |
| `birth_date` | `YYYY-MM-DD`, 1900-01-01 … московская сегодня | `draft.date` (день и месяц с ведущим нулём) |
| `place_id` | `Place.id` справочника | `draft.place.selected.id` |
| `time` | `{kind: 'unknown'}` или `{kind: 'known', value: 'HH:MM', source: document\|family\|approximate, accuracy_minutes: 0\|15\|30\|60}` | `draft.time`: `hhmm` через `normalizeTime`, `accuracy` или `accuracyBySource[source]` |

**Ответы**

| Статус | `code` | `fields` | Смысл |
|---|---|---|---|
| 200 | — | — | `ProfileCheck {profile, place}`: нормализованная анкета (имя без пробелов по краям) и место справочника |
| 400 | `validation_failed` | нет | Тело не разобрано: не JSON, неизвестные поля, неверная структура |
| 422 | `validation_failed` | все нарушенные поля сразу | Нарушено правило значения |
| 422 | `place_not_found` | `place_id` | Места нет в справочнике |
| 422 | `birth_time_nonexistent` | `time.value` | Время пропущено переводом часов вперёд |
| 422 | `birth_time_ambiguous` | `time.value` | Время повторилось при переводе назад; в V2 — только ошибка поля (Р7) |
| 429 | `rate_limited` | нет | Лимит частоты |
| default | `internal_error` и др. | нет | Сбой сервера |

Ключи `fields` — пути полей запроса; значение — текст на русском для показа. Привязка к блоку и шагу: `name` → имя / `name`, `birth_date` → дата / `date`, `place_id` → место / `place`, `time.*` → время / `time`.

**Мок** (`frontend/src/mocks/profileChecks.ts`, обработчик в `handlers.ts`): правила значений повторены независимо от `features/intake/validation.ts`; место ищется в синтетическом справочнике `mocks/places.ts`. Переводы часов мок не вычисляет. Переключатель на URL страницы `?profile-check=`: `slow` (1,5 с), `error` (503), `rate-limited` (429), `nonexistent`, `ambiguous` (только для известного времени).

### 0.3. Состояния

| Состояние | Условие | Поведение |
|---|---|---|
| Неполный черновик | `firstIncomplete(draft) !== null` или черновика нет | На review не попасть: `replace` на первый незаполненный шаг, как `reachableStep` SCR-02 §0.6 |
| Проверка | запрос в пути | Сводка из черновика видна сразу; «Продолжить» не ведёт дальше; индикатор — только если ответ дольше 300 мс |
| Готово | 200 | «Данные проверены»; «Продолжить» → `/create/access` |
| Ошибка поля | 422 `validation_failed` / `place_not_found` / `birth_time_nonexistent` | Текст сервера в блоке поля; сводка ошибок в строке статуса; «Изменить» ведёт на шаг |
| Повторяющееся время | 422 `birth_time_ambiguous` | Как ошибка поля времени; выбора двух вариантов нет (Р7) |
| Сбой проверки | 429, 5xx, сеть, 400 | Понятное сообщение и «Проверить ещё раз» (Р6). 400 — ошибка клиента, пользователь её не исправит, поэтому показывается как сбой |
| Повторная проверка | после «Проверить ещё раз» | Как «Проверка»; кнопка повтора остаётся на месте, неактивна до ответа |
| Reduced motion | `prefers-reduced-motion` | Без stagger и акцентов, короткий fade |

### 0.4. Критерии приёмки

- E2E-03: review показывает корректный профиль; «Изменить» возвращает на шаг с сохранением всех полей.
- MOT-02: назад/вперёд между review и шагами сохраняет значения.
- MOT-03: серверная ошибка поля не теряет данные, нет мерцаний и прыжков фокуса.
- M04: «Продолжить» не создаёт заказ; в сети нет запросов к заказам и доступам.
- `profile-checks` вызывается при каждом входе на review, включая возврат после «Изменить» (Р5); повтор — только по нажатию «Проверить ещё раз», без автоматических повторов.
- Без данных рождения в URL; все состояния §0.3 воспроизводятся моком; axe без нарушений; клавиатура; reduced motion; fallback без WebGL.
- Нет сдвигов основных элементов при асинхронной проверке (§0.9); рост блока с длинной ошибкой допустим (Р11).
- «Изменить» открывает шаг с сохранёнными данными; подтверждение или «Назад» возвращают сразу на review; обычный порядок шагов без режима редактирования не меняется (Р10).
- Контракт: мок типизирован сгенерированной схемой (`vue-tsc`), `make check-gen` чистый после коммита, `contract_test.go` валидирует спецификацию.

### 0.5. Визуальная спецификация

**Идея.** На шагах SCR-02 каждый ответ вписывался в подчёркнутое поле. На review четыре ответа стоят в одной колонке на тех же подчёркиваниях и в том же кегле, как страница анкеты, заполненная от руки. Это и есть editorial-сводка: типографика и ритм, без карточек, таблиц и рамок. Сцена — кадр шага времени, без движения камеры.

**Токены — только существующие** (DESIGN_SYSTEM §4, `ui/tokens.css`). Новых цветов и шрифтов нет.

| Роль | Токен / значение |
|---|---|
| Фон, сцена | `--cosmos-bg`, кадр `review` = `intake.time` |
| Ответ | `--cosmos-text`; до акцента — `--cosmos-muted` (§0.10) |
| Подпись блока, вторая строка | `--cosmos-muted` / `--cosmos-faint` |
| Подчёркивание ответа | `--cosmos-line`; во время акцента — `--cosmos-gold` |
| «Изменить», знак «проверено» | `--cosmos-gold-light` |
| Ошибка | `--cosmos-danger` + иконка, как ошибка `Field` в SCR-02 |
| Фокус | `--cosmos-focus`, кольцо как в SCR-02 |

**Типографика** (DESIGN_SYSTEM §5, шрифты SCR-01/02):

| Элемент | Desktop | Mobile | Начертание |
|---|---|---|---|
| Заголовок, строка 1 | `clamp(40px, 3.6vw, 60px)` | `clamp(32px, 8.6vw, 36px)` | светлая sans |
| Заголовок, строка 2 | тот же кегль | тот же | золотая italic serif |
| Вводный абзац | 17px / 1.5 | 16px / 1.5 | sans, `--cosmos-muted` |
| Подпись блока | микроподпись SCR-02 («ИМЯ») | та же | sans uppercase, tracking как в `Field` |
| Ответ | 28px / 1.2 (как текст поля SCR-02) | 24px / 1.2 | светлая sans |
| Вторая строка, ошибка | 15px / 1.45 | 15px / 1.45 | sans |

Заголовок мельче вопроса шага (`clamp(44px, 4.6vw, 72px)`) (C-R4). На 1440×900 прокрутка до «Продолжить» допустима (Р13).

**Тексты** (предложение, утверждает владелец, C-R5):

- Заголовок: «Проверь» / «свою историю.» (вторая строка — золотая italic serif). Перекликается с вопросом шага 03.
- Вводный абзац: «По этим данным мы рассчитаем карту. Любой пункт можно изменить.»
- Блоки:

| Подпись | Ответ | Вторая строка |
|---|---|---|
| ИМЯ | Анна | Так будет подписана карта. |
| ДАТА РОЖДЕНИЯ | 12 марта 1990 | понедельник |
| МЕСТО РОЖДЕНИЯ | Казань | Республика Татарстан · Россия |
| ВРЕМЯ РОЖДЕНИЯ (известно) | 14:30 | По документу, до минуты |
| ВРЕМЯ РОЖДЕНИЯ (неизвестно) | Неизвестно | Карта будет построена без домов и асцендента. (Р9) |

Подписи источника и точности — как в SCR-02 §0.5: «По документу» / «Со слов родных» / «Примерно»; «до минуты» / «±15 мин» / «±30 мин» / «±1 час». Дата и место форматируются теми же функциями, что на шагах (`formatDate`, строка выбранного города).

- Действие блока: «Изменить», доступное имя «Изменить имя», «Изменить дату рождения», «Изменить место рождения», «Изменить время рождения» (видимый текст входит в имя, WCAG 2.5.3).
- Кнопки: `PrimaryCTA` «Продолжить», ссылка «← Назад» (на шаг 04), как пара «Далее / Назад» в SCR-02.
- Прогресс: линия `ProgressStep` остаётся с шага 04 со всеми четырьмя заполненными сегментами; счётчик `04 / 04` уходит (opacity, 160 мс). Для ассистивных технологий — «Анкета заполнена».

**Что намеренно не используется:** карточки и рамки вокруг блоков, таблица «поле — значение», нумерация блоков, иконки у подписей, разделители между блоками, плавающая или прибитая к низу кнопка.

### 0.8. Состояния: визуально

Все состояния меняют содержимое заранее зарезервированных мест (§0.9). Ответы и подчёркивания остаются на месте всегда.

**Проверка** (первые 300 мс ничего не меняется: быстрый ответ не мигает):

```
│  [ Продолжить → ]   ← Назад          кнопка: aria-disabled, opacity 0.5 после 300 мс
│  ─── Сверяем данные…                  тонкая бегущая линия, как «Ищем…» в SCR-02
```

**Готово:**

```
│  [ Продолжить → ]   ← Назад          кнопка активна
│  ✓ Данные проверены.                 золотая отметка, --cosmos-muted
```

**Ошибка поля** (пример: дата и место):

```
│  ДАТА РОЖДЕНИЯ                         Изменить   ← --cosmos-gold-light, подчёркнут
│  13 ноября 2026
│  ───────────────────────────── (--cosmos-danger)
│  ⚠ Дата не может быть позже сегодняшней.          ← вместо второй строки
│  …
│  МЕСТО РОЖДЕНИЯ                        Изменить
│  Казань
│  ─────────────────────────────  (--cosmos-danger)
│  ⚠ Этого места нет в справочнике. Выбери город заново.
│  …
│  [ Продолжить → ]   ← Назад          aria-disabled
│  Нужно поправить: дата рождения, место рождения.   ← пункты — ссылки на шаги
```

Повторяющееся время (`birth_time_ambiguous`) выглядит так же: ошибка в блоке времени с текстом сервера, «Изменить время рождения» ведёт на шаг 04. Двух вариантов на выбор нет (Р7).

**Сбой проверки и повтор** (429, 5xx, сеть, 400):

```
│  [ Продолжить → ]   ← Назад          aria-disabled
│  Не удалось проверить данные. Проверь соединение      ← для 429 — текст сервера
│  и попробуй ещё раз.                [ Проверить ещё раз ]
```

Текст: `detail` ответа, если он есть (для 429 мок отдаёт «Слишком много проверок подряд. Подожди минуту и попробуй снова.»); иначе — «Не удалось проверить данные. Проверь соединение и попробуй ещё раз.» «Проверить ещё раз» — вторичная кнопка (`SecondaryCTA`-стиль без кольцевого знака), не спорит с «Продолжить». Во время повторной проверки она остаётся на месте и неактивна (`aria-disabled`), текст статуса — «Сверяем данные…».

### 0.9. Стабильность компоновки

- Сводка строится из черновика синхронно, до ответа сервера: все четыре блока имеют окончательную высоту с первого кадра.
- Вторая строка блока — слот с минимальной высотой в одну строку. Ошибка **заменяет** вторую строку, а не добавляется под неё. Длинная ошибка не обрезается: блок с ошибкой естественно растёт, блоки ниже сдвигаются только на эту разницу (Р11). Подписи, ответы, «Изменить» и кнопки при проверке не двигаются.
- Строка статуса стоит **под** кнопками: её высота меняется только в состоянии сбоя (появляется кнопка повтора), и сдвигается лишь заметка о черновике внизу. Кнопки и блоки не двигаются ни в одном состоянии.
- Ответ сервера отображается, только если отличается от черновика по смыслу (например, другое написание места): текст меняется кроссфейдом 160 мс на месте. Имя без пробелов по краям сводка показывает и до ответа.
- Длинные значения (60 символов имени, «Петропавловск-Камчатский · Камчатский край · Россия») переносятся по словам, `overflow-wrap: anywhere` для слов без пробелов; высота известна до показа.
- Шрифты — те же, что на шаге 04, уже загружены: смены метрик нет.

### 0.10. Фокус и клавиатура

**Куда ставится фокус**

| Событие | Фокус |
|---|---|
| Вход с шага 04 («Далее»), кнопками браузера, после «Изменить» | На заголовок `h1` (`tabindex="-1"`) в момент начала перехода; на всех устройствах (полей нет, клавиатура не поднимается) |
| Первая загрузка / перезагрузка review | На заголовок после первого кадра |
| Пришёл ответ 200 / 422 / сбой, пока пользователь читает | Не переносится; изменение объявляет строка статуса (`role="status"`, `aria-live="polite"`) |
| Нажатие «Продолжить», пока проверка идёт или есть ошибки | Фокус на строку статуса (`tabindex="-1"`), при необходимости она прокручивается в видимую область (`scrollIntoView({block: 'nearest'})`) |
| Нажатие «Проверить ещё раз» | Фокус остаётся на ней; после ответа 200 кнопка исчезает, фокус переходит на «Продолжить» |
| Нажатие «Изменить» / пункта сводки ошибок | Как вход на шаг в SCR-02: desktop — в поле шага, сенсорные экраны — на заголовок (C26) |

**Порядок Tab:** «На главную» → «Изменить имя» → «Изменить дату рождения» → «Изменить место рождения» → «Изменить время рождения» → «Продолжить» → «Назад» → пункты сводки ошибок / «Проверить ещё раз» (если есть) → «Замедлись». DOM-порядок совпадает с визуальным: внутри блока — подпись, ответ, вторая строка или ошибка, затем «Изменить»; визуально «Изменить» поднимается на строку подписи через grid, а не через `order`.

**Семантика:** сводка — `<dl>`: подпись — `<dt>`, ответ, вторая строка и действие — `<dd>`. Ошибка в `<dd>` с иконкой `aria-hidden` и текстом «Ошибка:» для скринридера. «Продолжить» неактивна через `aria-disabled="true"`, а не `disabled`: кнопка остаётся в порядке Tab и сообщает причину.

**Клавиши:** Enter / Space — на любой кнопке и ссылке; других горячих клавиш нет. Кольцо фокуса — `--cosmos-focus`, как в SCR-02; цели не меньше 44×44 (у «Изменить» — за счёт внутренних отступов, видимый текст меньше).

### 0.12. Критерии утверждения (стадия 0, этап 2)

Владелец утверждает по этому документу:

1. Идея сводки (§0.5): ответы на подчёркиваниях, без карточек, рамок и нумерации.
2. Тексты (C-R5): заголовок, вводный абзац, вторые строки, статусы и сообщения об ошибках.
3. Каркасы desktop и mobile (§0.6, §0.7) и уменьшенный кегль заголовка (C-R4).
4. Визуальные состояния (§0.8) и размещение строки статуса под кнопками.
5. Фокус и порядок Tab (§0.10).
6. Хореография M04 (§2).
7. Путь после «Изменить» (C-R3).

После реализации (стадии 1–6) — снимки `make visual` на 1440×900, 1920×1080, 768×1024, 390×844, 375×667 для состояний: готово (время известно), готово (время неизвестно), проверка (`?profile-check=slow`), ошибка нескольких полей (переопределение мока в тесте), `place_not_found` (черновик с несуществующим `place_id`), `nonexistent`, `ambiguous`, `error`, `rate-limited`, длинные значения, reduced motion.

## 2. Хореография (план стадии 2, M04)

Токены — из SCR-02 §2.1, новых нет: `stepEnter` 420 мс `out`, `stepExit` 200 мс, `micro` 160 мс, `cinematic` для камеры.

**Вход с шага 04 («Далее»)**

| Время | DOM | Сцена |
|---|---|---|
| 0 мс | Проверка шага 04 прошла, `push('/create/review')`. Фокус — на `h1`. Запрос `profile-checks` уходит сразу | Кадр тот же (`review` = `intake.time`), камера стоит |
| 0–200 мс | Блок шага 04 уходит влево (M03): opacity, сдвиг 20px, blur 2px. Счётчик `04 / 04` гаснет, линия прогресса остаётся | — |
| 80–500 мс | Колонка review приходит справа одним слоем: opacity, сдвиг 20→0, blur 2→0, 420 мс, `out`. Ответы сразу на месте, в цвете `--cosmos-muted` | — |
| 300–870 мс | **Акценты M04**: по блокам с шагом 90 мс (300, 390, 480, 570 мс) подчёркивание прорисовывается слева направо золотом (`scaleX` 0→1, 300 мс, `out`), ответ переходит из `--cosmos-muted` в `--cosmos-text` (300 мс). Затем золото подчёркивания остывает до `--cosmos-line` (400 мс) | — |
| ≈ 1000 мс | Всё на месте | — |

Акцент — единственное «нефункциональное» движение экрана (Excessive Motion). Текст читается с первого кадра входа: акцент меняет только цвет ответа и линию, не прозрачность и не положение. Состояние проверки на акценты не влияет и их не прерывает.

**Другие входы.** Кнопки браузера и возврат после «Изменить» → прохождение шагов — так же. Первая загрузка — как первая загрузка шага SCR-02 §0.6 п. 3 (600 мс, подъём 12px), затем те же акценты.

**Выход.** «Изменить» — зеркальный M03 «Назад»: колонка уходит вправо (200 мс), шаг приходит слева, камера летит в кадр шага (1000 мс, `cinematic`). «Назад» — то же для шага 04, камера стоит. «Продолжить» — колонка уходит влево (200 мс); вход SCR-04 описывает его журнал.

**Смена состояний.** Строка статуса: кроссфейд 160 мс. Бегущая линия проверки — `transform`, только после 300 мс. Ошибка в блоке: вторая строка гаснет за 120 мс, ошибка появляется (opacity, сдвиг −4→0, 160 мс), подчёркивание → `--cosmos-danger` за 160 мс; без тряски. «Проверить ещё раз» появляется opacity 160 мс.

**Reduced motion.** Колонка появляется opacity 200 мс, уход 120 мс. Без сдвигов, blur и акцентов: ответы сразу `--cosmos-text`, подчёркивания сразу `--cosmos-line`. Бегущая линия заменяется статичным текстом «Сверяем данные…». Смена состояний — только opacity.

**Без WebGL.** Сцена статична в кадре шага 04; на SCR-03 она не движется, fallback ничего не меняет.

Ревью motion — таблица Before / After / Why на стадии 4.

## Журнал реализации

**Ж1. Состав.** `features/intake/ReviewView.vue` (экран), `features/intake/review.ts` (чистые функции: `toProfile`, `reviewItems`, `fieldStep`, `checkFailure`, `requestProfileCheck`), `app/routes.ts` (`/create/review` → `ReviewView`), `features/intake/guard.ts` (guard неполного черновика), `api/problem.ts` (`ApiProblem.fields`), `ui/ProgressStep.vue` (флаг `done`). OpenAPI, моки, сцена и SCR-01 не менялись.

**Ж2. Режим редактирования (Р10).** «Изменить» открывает `/create?step=<шаг>&from=review`. Флаг `from=review` говорит только, куда вернуться; данных в URL нет. В `IntakeView.vue` три локальные правки: в режиме редактирования главная кнопка называется «Проверить данные» (как на шаге 04) и после проверки поля ведёт на review; «Назад» тоже возвращает на review; уход на review идёт влево (M03), остальные уходы — как раньше. Возврат использует `router.back()`, если review — предыдущая запись истории, поэтому история не растёт. Без флага порядок шагов прежний (тест).

**Ж3. Guard.** `/create/review` с неполным черновиком делает `replace` на первый незаполненный шаг **с флагом редактирования**: ответив, пользователь сразу возвращается на review, и guard ведёт к следующему пропуску. Guard шагов сохраняет флаг при исправлении ссылки.

**Ж4. Проверка.** Запрос уходит при каждом монтировании review (Р5); прежний запрос отменяется `AbortController` при уходе. Индикатор «Сверяем данные…» и приглушение «Продолжить» — только если ответ дольше 300 мс; после «Проверить ещё раз» индикатор виден сразу. `checkFailure`: 422 с известными полями → ошибки по блокам (два сообщения `time.*` объединяются); 400, 429, 5xx, сеть, 422 без известных полей → сбой с повтором. Текст сбоя — `detail` сервера, иначе «Не удалось проверить данные. Проверь соединение и попробуй ещё раз.»

**Ж5. Отличие от §0.8.** Сводка ошибок «Нужно поправить: …» — пункты-кнопки внутри строки статуса (`role="status"`), а не ссылки: каждая ведёт на шаг так же, как «Изменить».

**Ж6. Тесты.** `review.spec.ts` (27: профиль из черновика, тексты блоков, привязка полей, разбор ответов, запрос через MSW), `ReviewView.spec.ts` (11: четыре ответа и фокус, переход после 200, блокировка до ответа, ошибка поля и «Изменить», сбой и повтор с переносом фокуса, 429, новый запрос на каждом входе; режим редактирования IntakeView: возврат после подтверждения и по «Назад», остаётся на шаге при ошибке, обычный порядок без флага), `router.spec.ts` (+2: guard review, сохранение флага).

**Ж7. Визуальная приёмка (Р12).** Снимки Playwright на MSW с `?scene=freeze`: 1440×900, 1920×1080, 390×844, 375×667; проверка (`?profile-check=slow`) и сбой (`?profile-check=error`) на 1440×900. Кадр сцены шага 04 и review совпадает попиксельно (1440, 390); текст не заходит на планету; горизонтальной прокрутки нет; кнопки и вторые строки не обрезаны; ошибок консоли нет. На 1440×900 высота страницы 1162 px, «Продолжить» на 956 px — принято владельцем (Р13).

**Ж8. E2E и проверки.** `e2e/smoke/review.spec.ts` (15): E2E-03 (профиль, тело запроса, «Изменить» → другой город → «Проверить данные» → review с сохранёнными ответами, второй запрос по Р5, «Назад» в режиме редактирования, «Продолжить» → `/create/access` без запросов к заказам и доступам, нет данных в URL), обычный порядок шагов, неизвестное время, MOT-02, guard, MOT-03 (ошибка поля, фокус на статус), сбой без автоповтора и ручной повтор, стабильность при медленной проверке, axe (готово, ошибка поля, сбой), reduced motion (fade без stagger и пролёта), без WebGL (постер), телефоны 390 и 375. Весь smoke-набор (85, с SCR-01 и SCR-02) зелёный трижды подряд.

**Оставшиеся замечания (не дефекты, решение владельца — при следующих экранах):** на review сегменты прогресса встают на место ушедшего счётчика «04» (сдвиг ≈30 px); на 1920×1080 колонка и заголовок ограничены 560 px / 60 px, как в SCR-02; «Проверить ещё раз» стоит строкой ниже текста сбоя. Снимки `make visual` для review в эталонный набор не добавлены.
