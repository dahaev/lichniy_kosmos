# Личный космос 2.0 — правила агентов

Проект проектируется и пишется с нуля: Go + Vue 3/TypeScript + PostgreSQL. Legacy-документы — только источники описания прежнего поведения, **не** инструкция переносить старую архитектуру или код.

## Приоритет требований
1. Новые явно согласованные решения в `docs/PROJECT_DECISIONS.md`.
2. `docs/frontend/SCREEN_SPEC_MVP_v2.md`, `DESIGN_SYSTEM.md`, `MOTION_SPEC.md`, `FRONTEND_ACCEPTANCE.md` — для новых пользовательских сценариев и UI.
3. `docs/product/PRODUCT_MVP_SCOPE_v1.md` — перечень MVP-функций и инварианты, кроме уточнённого порядка шагов из п. 1–2.
4. `docs/legacy/*.md` — справочные сведения и эталон старого поведения.

При противоречиях фиксируй их и предлагай согласование; не делай молчаливых предположений.

## Текущие ограничения
- Работать с новым проектом, не трогать старый production и живую БД.
- Не писать код до утверждения архитектуры. На первом задании агент делает только план и документы.
- Не включать оплату на сайте, Ozon Seller API, совместимость и прогноз в MVP.
- Дизайн нового публичного сайта строго строить вокруг `docs/frontend/references/hero-approved.png`. Это эталон первого экрана, не готовый код и не подтверждённый набор анимаций.
- Не хранить пароли, токены, настоящие коды активации и данные клиентов в Git/промптах.
- Никаких повторных платных вызовов ИИ при неизвестном исходе операции.
